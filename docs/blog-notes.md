# 블로그용 정리 — "정읍 지금" 만들기 (연재 노트, 2026-11-20 갱신)

> 비전문가(공인중개사)가 AI와 대화만으로 지역 3D 지도 앱을 만든 과정. 각 단계는 글 한 편 분량으로 쓸 수 있게 나눴습니다.

## 1편. 왜 만들었나
- 동네에 이미 강한 온라인 모임(밴드)이 있지만 글이 흘러가고 위치가 없다
- 목표: "지금 이 순간의 동네 정보"를 지도 위에 (교통·행사·웨이팅·사건사고·생활정보)
- 순서: 실시간 정보 + 커뮤니티 먼저, 부동산 기능은 나중에 (그래야 사람이 모인다)

## 2편. 뼈대 만들기 — 3D 지도와 무료 호스팅
- 무료 지도(MapLibre + OpenFreeMap)로 건물을 높이만큼 세워 3D 지도
- GitHub Pages로 무료 배포, Supabase(무료 플랜)로 제보 저장
- 교훈: 처음부터 큰 서버를 쓰지 않아도 된다

## 3편. 제보와 자동 만료
- 지도를 길게 눌러 제보 → 관리자 승인 후 노출
- 종류별 자동 만료(교통 6시간, 웨이팅 3시간, 사건사고 24시간 등)
- 교훈: "오래된 정보가 남지 않게"가 신뢰의 핵심

## 4편. 스마트폰 앱처럼 — PWA와 설치
- 홈 화면에 설치되는 웹앱(PWA), 새 버전 자동 반영
- 카카오톡 안에서는 설치가 막힌다 → 외부 브라우저로 여는 안내 띠
- 교훈: 지인에게 카톡으로 링크를 돌릴 때 가장 먼저 막히는 곳

## 5편. 주소 검색 — 도로명과 지번
- 도로명 주소와 지번 주소 둘 다 찾기 (공공데이터로 지번 색인 직접 생성)
- 안 되는 케이스를 사용자가 직접 찾아 알려주며 고침
- 교훈: 데이터가 없으면 "있는 데이터로 만들어 쓰는" 방법을 찾는다

## 6편. 아파트와 야간 모드
- 아파트 색·창문 패턴, 낮/밤 모드, 날씨 효과(비·눈)
- 시행착오: 불빛이 "불빛 같지 않다", 밤에 건물만 어둡다 → 여러 번 갈아엎음
- 교훈: 화면 완성도는 캡처를 보며 한 단계씩 (AI도 직접 못 본다)

## 7편. 커뮤니티 — 가볍게 참여하게 만들기
- 글쓰기는 부담 → "오늘의 맛집 TOP 3" 하루 한 표, 👍/👎 한 번 누르기
- 익명 악용 우려로 닉네임 글쓰기는 보류, 알바·중고·부동산은 "준비 중" 탭으로 비전 제시
- 교훈: 처음엔 누르기만으로 참여할 수 있게

## 8편. 관리자 도구
- 가게 이름·위치 수정을 일반 지도 화면 그대로에서 (별도 관리자 지도는 너무 달라 폐기)
- 공지 띠(긴급 빨강/일반 파랑, 시간 지정), 수동 날씨, 편집 기록 되돌리기, 정보 수정 요청함
- 교훈: 운영자가 쓰기 쉬워야 앱이 유지된다

## 9편. 사진 첨부와 용량 관리
- 허위 제보 방지용 사진 첨부, 폰에서 축소해 업로드, 만료 시 자동 정리
- 교훈: 기능을 넣기 전에 "서버 용량"부터 계산

## 10편. 첫 방문 안내와 제보 흐름 개선
- 튜토리얼(처음 한 번만), 제보 시 헤더가 위로 올라가 지도를 크게
- 교훈: 처음 온 사람의 첫 1분을 설계하라

## 11편. 지도 디자인 고도화
- 건물 색감·낮밤 조명·도로 차선·야간 라벨 가독성 (단계별, 캡처 확인)
- 성능: 밤 화면 CSS 필터를 레이어로 교체해 버벅임 감소
- 교훈: 예쁜 것과 가벼운 것은 따로 챙겨야 한다

## 12편. 커뮤니티를 다크 카드로, 제보에 "남은 시간" 달기
- 커뮤니티 화면 다크 카드, 맛집 투표 퍼센트 막대, 가벼운 전환 효과
- 제보 카드에 만료까지 남은 시간 배지(1분마다 글자만 갱신, 화면 안 볼 때는 정지)
- 의문: 만료 시간은 관리자가 정할까, 규칙으로 정할까 → 분류별 규칙 + 예외 수동(교통 3h / 웨이팅 2h / 사건 12h / 행사·정보 24h 제안)
- 교훈: 시간 표시 하나로 "살아있는 정보" 느낌이 난다

## 13편. 뒤로가기 버튼과의 전쟁
- 증상: 커뮤니티에서 뒤로가기를 누르면 앱이 통째로 꺼짐
- 원인: 브라우저는 "사용자가 터치한 적 없는" 화면의 기록을 건너뛴다(pointerdown은 인정 안 됨, pointerup/click만 인정)
- 해결: 화면을 열 때 전용 기록을 하나 쌓고, 닫을 때 같이 정리
- 교훈: 앱처럼 보여도 브라우저 규칙 위에서 움직인다 / 폰 실제 기기로 확인 필수

## 14편. 지도가 너무 복잡하다 — 덜어내기
- 상가 점 1,600여 개 → **음식점·카페·술집만** 표시, 중복 제거
- 점이 작아 눌리지 않음 → 눈에 안 보이는 "큰 터치 영역" 레이어
- 관공서(시청·주민센터) 레이어 추가, 글씨 키우기. 주소 데이터가 옛것이라 한계 인정
- 제보 선택창에 "가게 정보 수정", "없는 가게 알려주기" 추가
- 교훈: 기능 추가보다 **빼기**가 사용성을 올린다

## 15편. 내 컴퓨터에서 안전하게 개발하기
- 로컬에서 편집·손님 화면·관리자 화면을 한글 이름 .bat 파일로 실행
- `?public=1`로 손님 시점 미리보기
- 실수 방지: 큰 작업 전엔 백업 브랜치, 배포는 버전 번호 올리기로 통일
- 교훈: 비전문가일수록 "되돌릴 수 있는 장치"를 먼저 만든다

## 16편. 웹푸시 알림 만들기 (가장 긴 디버깅 이야기)
- 목표: 손님이 제보를 올리면 사장님 폰·PC에 "📍 새 제보" 알림
- 구성: 알림용 키(VAPID) → 서비스워커 → Supabase Edge Function → DB 트리거
- 겪은 오류 순서(글 소재):
  1. 허용창이 안 뜸 → 권한 요청은 터치 직후 바로
  2. 키 형식 오류(500) → 비밀 키 재입력, 코드에 공백·따옴표 제거 보정
  3. 403 → 두 곳에 넣은 비밀 문자열이 달랐음
  4. 200인데 `ok:0` → 구독 기기 0대, 다시 등록
  5. 또 `ok:0` → 함수가 실패 이유를 말해 주지 않음 → **응답에 실패 사유를 넣어** 원인 발견
  6. 진짜 원인: DB 테이블 권한(service_role) 누락
- 교훈: 에러를 숨기지 말고 **원인이 보이게 만들어라**

## 17편. 삼성 인터넷은 알림이 안 온다? — 폰 알림 설정기
- 갤럭시 폴드8 삼성 인터넷: 알림 허용창이 아예 안 뜸(상태 default) → Chrome에서 등록하니 성공
- 관리자 알림은 사장님 폰 1대만 등록하면 되므로 Chrome 1회 사용으로 해결
- 손님 알림은 선택 기능, 필수 기능은 아님 → 앱 설치(홈 화면 추가) 유도가 현실적
- 교훈: 기능이 "되는 환경"과 "안 되는 환경"을 구분해서 설계

## 18편(예정). 디자인 UI 전면 개편
- 제미나이로 방향 잡기 → Claude로 구현하는 분업 (docs/gemini-brief.md)
- 소재: 색 통일, 상단 칩 단순화, 정읍 정체성(내장산 단풍), 고령자 친화 글씨

## 후보 소재 (연재 거리)
- 욕설·금칙어 차단 방법(금칙어 목록 + 글자 수 제한 + 신고 누적 숨김)
- 오늘의 1픽 맛집 배틀, 음식 사진 올리기(승인제라 용량 가볍게 관리)
- 제보 릴레이/지도 핑퐁(제보 공유 링크, 근처 제보 연결)
- 효과음·배경음
- 알바·중고·부동산 탭 실제 오픈(연락처 보호, 외국인 고용 책임 문구)
- 수익화 아이디어 정리

## 공통 팁 (글마다 넣기 좋은 것)
- AI에게는 "작업해"라고 할 때만 작업하게 규칙을 정했다 → 의도치 않은 변경 방지
- 비밀 키는 AI에게 주지 않고 공개용 키만 사용
- 큰 작업마다 새 대화로 나누고, 저장소에 인수인계 문서를 남긴다

- 사고를 풀 때는 AI가 "원인이 안 보이면 보이게 만드는 코드"부터 넣게 한다(16편)
- 큰 작업 전에는 백업 브랜치를 만든다(예: `backup/2026-11-20-push-ok`)

## 연재 운영 템플릿 (글 한 편마다)
1. **제목**: 문제나 결과가 보이게 (예: "알림이 안 와서 하루를 썼다")
2. **한 줄 요약**: 비전문가가 AI와 무엇을 해냈나
3. **상황**: 하려던 것 / 사용자 입장의 불편
4. **시도와 실패**: 에러 문구·캡처·원인 (실패담이 제일 읽힌다)
5. **해결**: 한 줄로 핵심 + 바뀐 화면
6. **교훈 한 줄**, **다음 편 예고**
- 분량: 1,000~1,500자, 캡처 2~4장
- 숨길 것: 비밀 키, 관리자 이메일, 개인 정보(캡처에서 가려서 올리기)
